## 1. 测试范围

覆盖完整训练闭环：工作台 → 简历解析（DOCX/PDF/粘贴/示例）→ JD 匹配 → 面试设置（人格/题量/侧重）→ 模拟面试（作答/流式/提示/跳过/进度/轨迹/刷新恢复）→ 复盘报告（五维/逐题/引用/导出/加入题库）→ 个人题库（掌握度/笔记/手动加题/去重/导出）→ 知识库（分类/BM25 搜索/详情/自定义文档增删）→ 面试记录 → 模型设置 → 移动端 → 安全与异常。

不在本轮范围：真实用户可用性测试、真实 LLM 供应商限流/计费、Safari 语音输入、扫描版 PDF OCR、多用户并发。

## 3. 缺陷与修复

| ID | 严重度 | 问题 | 影响 | 根因 | 修复 | 状态 |
|---|---|---|---|---|---|---|
| D-01 | 中 | 不支持格式 / 损坏 PDF / 旧版 `.doc` 返回 500 | 用户看到“服务异常”，无法判断文件问题 | `parseUpload` 异常未包装为 `HttpError` | 路由层捕获并返回 400 + 可操作提示 | 已修复，回归通过 |
| D-02 | 高 | 生成报告后仍可继续作答/提示/跳过 | 报告与作答数据不一致 | `finishSession` 未清空 `pending`，turn 只检查 pending | 清空 pending；turn/hint/skip 校验 `status=active` | 已修复，回归通过 |
| D-03 | 中 | 13MB 请求触发 `ECONNRESET` | 客户端看到 fetch failed，而非 413 | 超限时停止读取，连接被重置 | 预检 `Content-Length`，`req.resume()` 后返回 413 | 已修复，回归通过 |
| D-04 | 低 | 完成面试后工作台统计仍旧值 | 用户以为记录丢失 | 首页使用启动时缓存的 `state.stats` | 首页渲染前刷新 `/api/stats` | 已修复，回归通过 |
| D-05 | 低 | 手动重复加题出现重复卡片 | 题库数量与视觉不一致 | 前端无条件 `unshift` | 按 `item.id` 去重 | 已修复，回归通过 |
| D-06 | 低 | 模型服务不可达时提示 `fetch failed` | 用户不知道是网络、地址还是 Key | 未区分网络异常 | 捕获 `TypeError`，转为中文可操作提示 | 已修复，回归通过 |

> D-02 为唯一高严重度问题，修复后新增“已完成会话禁止继续操作”回归用例；D-01/D-03 的异常码与连接行为也纳入长期回归集。

## 4. 关键验证证据

- 真实 DOCX 解析：石浩田，3 段实习、2 个项目、质量分 96。
- 真实 PDF 解析：3 段实习、质量分 96。
- 示例简历完整闭环：解析 → JD 72 分 → 6 题题单 → 作答评分 → 报告 71 分 → 加入题库。
- SSE 事件顺序：`meta → delta… → evaluation → state → done`；单题五维齐全。
- LLM mock：题单 `source=llm`、流式回复、评估 `mode=llm`、报告 `mode=llm`；服务不可达时全部回退 `local` 并记录 `lastError`。
- 桌面 1440 / 移动 390 均无横向溢出；移动端菜单、快捷操作、报告首屏正常。
- XSS：题库内容 `<img src=x onerror=…>` 按文本渲染，未执行脚本。

## 5. 已知限制（非缺陷）

1. 本地规则引擎是启发式评分，语义理解有限；报告中明确标注“规则评分”。
2. 扫描版 PDF 无文字层，需改用 DOCX 或粘贴文本；不做 OCR。
3. 语音输入依赖浏览器 `SpeechRecognition`（Chrome/Edge），Safari 不支持。
4. 单进程 JSON 存储无并发锁，不适合公网多用户。
5. BM25 不含向量语义召回，行业新词可能漏检。
6. Agent 轨迹 JSON 导出/筛选为 V1.1 规划，当前为实时时间线。

## 6. 发布建议

核心闭环、异常处理与降级链路均已验证，无未关闭 P0/P1。建议进入 **30 人封闭灰度**，重点观察：

- 报告行动转化率（报告后 7 天内是否加入题库/复练）；
- 7 日内复练率与同题二次得分提升；
- 追问下的稳定性（是否出现连续“不知道”）；
- 模型降级率与单场 token 成本。
