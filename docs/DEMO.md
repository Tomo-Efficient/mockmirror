# 面镜 MockMirror · 演示脚本

## 3 分钟版（面试官 / 作品集）

**0:00 打开工作台**

> 这是面镜，一个 AI 面试教练。不是通用聊天机器人：它只问和你简历、JD 有关的问题，而且最后会告诉你每个分数是怎么来的。

**0:20 开始面试**

点「开始一场模拟面试」→「用示例简历试试」→ 展示解析结果：

> 它从 PDF/DOCX 里抽出了教育、两段实习、两个项目、6 条量化亮点，并给了一个解析质量分。质量低会提示你改排版，而不是硬着头皮往下走。

**0:50 岗位匹配**

点「用示例 JD」→「分析岗位匹配」：

> 它会识别岗位、算关键词覆盖，并明确告诉你缺哪几块。这里缺的是大模型、Agent、B 端经验——这些会进入后面的题单。

**1:10 选人格**

选「资深面试官」，6 题，开始：

> 三种人格不是换皮：同级会顺着你聊，资深会连续追问，直属经理会质疑你的资源和结果。

**1:30 作答**

回答第一题（30 秒左右）。观察右侧：

> 右边实时显示考察点、五维评分和 Agent 轨迹。刚才这次回答 76 分，它判断「结果量化」是优势，但「内容相关性」偏弱——因为我没有正面回答“最关键决策是什么”，而是先讲了背景。

**2:10 追问**

面试官追问口径：

> 这就是条件路由：回答里数字没有口径，它不会放过，会继续问一层。每题最多追问两次，避免变成审讯。

**2:40 报告**

点「结束并生成报告」：

> 报告不是一句“表现不错”。它有五维雷达、逐题证据、知识库依据、示范结构和 7 天行动清单。低分题可以一键进个人题库。

**3:00 收尾**

> 技术上它是 Node 原生 HTTP + 零构建前端，状态机编排 + BM25 检索；不配模型也能跑，配了模型追问会更自然。所有数据只存在本地。

## 10 分钟版（技术面）

### 1. 为什么不用 LangGraph / 现成框架？

> 这个产品的编排只有 7 个节点、3 条条件边，引入框架的收益小于调试成本。我用约 80 行实现了一个显式状态机：节点是纯函数，条件边是纯函数，trace 直接落到会话里。以后要换 LangGraph，只需要把 `StateGraph` 替换掉，节点逻辑不用动。

### 2. 为什么保留本地规则引擎？

> 三个原因：演示不能依赖 Key；模型故障时产品不能不可用；规则评分提供了一个可复算的 baseline，方便判断模型分数是否漂移。代价是语义理解有限，所以 UI 上明确标注「规则评分」，不假装它是模型。

### 3. 评分怎么保证不是瞎给？

> 五个维度、固定权重、每个维度都有可指出的证据；总分由分项加权得出，不由模型直接给。题型也会影响评分：问「口径」的题不会因为没用 STAR 就被判低分。报告里能看到每道题的分项和风险句。

### 4. RAG 具体怎么用？

> 索引三类文档：知识库、题库、岗位包。中文按 bigram 切，英文按词边界，BM25 打分。出题时召回候选题目，复盘时召回知识库要点，作为引用展示。没有向量库，是因为语料只有一百来条，BM25 足够且完全可解释。

### 5. 多轮上下文会爆吗？

> 每轮只带最近 8 条消息，更早的压成「已聊主题 + 最近回答摘要」，画像压到 1800 字，JD 压到 600 字。单题评估不带全量历史。一场 6 题大约 1.5 万 tokens。

### 6. 为什么前端不用 React？

> 页面只有 8 个，交互以表单和流式文本为主。原生 ESM + 自写 CSS 把构建链和依赖都省了，改一行刷新就生效。代价是组件复用靠函数，不靠框架——对这个规模是划算的。

### 7. 数据怎么存？

> 本地模式用单文件 JSON（tmp + rename 原子写入）；线上配置 `DATABASE_URL` 后使用 Neon，按用户隔离。当前仍是单行 JSON 状态，适合单实例演示，不适合高并发多实例。

### 8. 怎么验证效果？

> 三层：离线用固定简历和回答跑回归；模型层用 mock OpenAI 服务验证流式、JSON、超时降级；产品层用 Puppeteer 跑桌面和移动端全流程，检查 console error 和横向溢出。评分本身还需要人工抽检，规则评分不能替代人工判断。

## 现场可能被问的问题

**Q：为什么不做实时语音面试？**
> 实时语音的延迟、打断、噪声处理是另一个工程问题，会把 MVP 拖长。先用文字把「问什么、怎么追问、怎么复盘」跑通，语音只作为输入方式（浏览器 SpeechRecognition），不做存储。

**Q：和市面上的 AI 面试产品差在哪？**
> 它们大多卖「题库 + 打分」，面镜卖「针对你的简历追问 + 可解释的复盘」。另外它是本地优先的，简历不出机器。

**Q：商业模式？**
> 个人版免费/买断，B 端卖给高校就业中心和训练营，按席位收费。当前阶段优先验证「报告是否真的能改变下一次表现」，而不是扩功能。

**Q：如果模型胡说八道？**
> 三道闸：Prompt 只允许使用简历事实；评估与报告都要求引用具体回答；总分由服务端重算。发现编造可以在报告里直接看到。
